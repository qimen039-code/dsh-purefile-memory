## 3. 归因分析：方向正确，还是与高分系统同构？

**结论：两者都是，且各有明确证据。**

### 3.1 原始设计（会话 b2dbae8c）对 LoCoMo 分数的贡献 ≈ 0
分层存储（L0-L3）、活期/封存、supersede/审计链、route 连接器、brief 去重——这些核心构件
**没有任何一个出现在榜单系统里**，因为它们解决的是"agent 工作记忆的可信与可审计"问题，
不是"问答检索命中率"问题。方向没有错，但它本来就不是为这张榜单设计的。

### 3.2 拿到分数的部分，确实与 Mem0/Zep 趋同构
| 能力 | 我们 | Mem0/Mem0g/Zep | 判定 |
|---|---|---|---|
| 原子化抽取 | LLM 抽 facts（statement/speakers/entities/date/kind） | LLM 抽 memories（ADD/UPDATE/DELETE） | **同构** |
| 实体关联 | 确定性关联图（实体/说话人/会话） | Mem0g/Zep 实体图谱 | **同构**（实现不同：零嵌入） |
| 语义召回 | 词面候选 + LLM 重排（0-3 分） | 嵌入向量召回 | **趋同异构**：他们靠向量，我们靠"词面宽召回+LLM 精排"，效果等价但工程路线不同 |
| 时间 | ingest 时强制解析为绝对日期 | 存原文，查询时算 | **我们独有且被验证**（temporal 碾压的根因） |

趋同不是抄袭：这些改动全部来自 123 道失败题的第一性原理归因（bench/results/v4-failures.txt）。
行业在同一问题上收敛到同一批解，恰恰说明这些是该问题的正确解——高分系统的设计验证了
我们的方向，而不是我们的分数靠了它们。

### 3.3 我们独有、榜单系统没有、且被消融验证的东西
1. **ingest 时时间解析**（temporal 0.78-0.86 的直接来源）
2. **digest 问题条件化整合**（把 top-k 事实先整合成一段完整记忆再答题——枚举/对比题的来源）
3. **零嵌入架构**（无向量库依赖，纯词面+图+LLM 精排——成本与工程复杂度低一个量级）
4. **四层 canonical + 审计链**（对 QA 无贡献，对用户真实目标[可审计/不污染/可交接]是核心——
   这是原始设计的正确性，只是不在这张榜单上体现）

### 3.4 最大未验证风险（用户点名的）
dev 迭代 6 轮全部基于 LoCoMo 失败题 → **对本数据集措辞分布过拟合的风险真实存在**。
当前证据不支持也不否定泛化：adversarial（题目改写+前提置换）1.00 说明措辞鲁棒性存在，
但跨语料、跨题型未验证。→ 泛化验收计划（复现性/等价扰动/混沌语料/侦探链/因果序/全局关系）
已立项，恢复后先做这个再谈分数。
